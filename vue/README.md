# eSIM Landing — Vue

Самостоятельная копия React-эталона на Vue 3.5.35. При первоначальной миграции исходный React-проект в корне репозитория не изменялся. Позднее по отдельному запросу в обе версии внесено исправление прозрачного видео и вращения чипа в Chrome на iOS (см. ниже). Весь контент, база устройств, шрифты и 176 исходных assets находятся внутри этого приложения; ссылок на соседний React-проект для запуска нет.

## Запуск

Требуется Node.js 20.19+ либо 22.12+.

```sh
cd vue
npm ci
npm run dev
```

Dev: http://127.0.0.1:5174. Production: `npm run build`, затем `npm run preview` — http://127.0.0.1:4174. Проверки: `npm test`.

## Непрерывная scroll-сцена (история реализации)

Сохранены одна сцена, один нативный sticky-stage и исходная схема наложения. Базовая высота сцены вычисляется из конца второй ширмы (`4243svh`), дополнительно добавляется 0,307 высоты viewport для появления FAQ с округлением вверх. Новых pin-spacer, transform-контейнеров или фоновых fullscreen-секций нет. Прозрачный checker находится над тем же градиентом, который возвращается за текстом безопасности.

Последовательность: **hero → белая шторка → рулетка → раскрытие оранжевого фона/чип → строка преимуществ → шесть преимуществ → серый блок «eSIM — это…» → четыре тезиса → безопасность → возвращение оранжевого фона → checker**.

React wheel-handler, spring scroll и собственные RAF-циклы не перенесены. Один GSAP timeline анимирует числовые каналы, ScrollTrigger привязывает его к нативному scroll. Изолированные render-функции переводят каналы в исходные transform/clip-path/blur/opacity и `video.currentTime`. Они кешируют узлы и сами не запускают циклы. Нормальный scrub — 0,24 с; Reduce Motion — непосредственное следование scroll с упрощённой декоративной геометрией. Профиль инерции Lenis отличается от собственной пружины эталона, поэтому математическое совпадение каждого промежуточного кадра при резком wheel не заявляется.

Основные тайминги в высотах viewport:

| Канал | Начало → конец |
| --- | --- |
| Белая шторка | 0 → 1 |
| Рулетка | 1,28 → 4,35 |
| Раскрытие фона / чип | 4,28 → 6,149 / 4,3868 → 6,0956 |
| Строка преимуществ | 6,95 → 12,45 |
| Шесть преимуществ | 12,45 → 20,45 |
| Два оборота чипа | 6,95 → 22,95 |
| «eSIM — это…» | 20,55 → 26,05 |
| Четыре тезиса | 26,23 → 33,43 |
| Безопасность | 33,68 → 39,68 |
| Возврат градиента | 37,16 → 39,41 |
| Подъём checker | 37,4 → 39,68 |
| Вторая ширма | 40,43 → 41,43 |
| Появление FAQ и баннера | 41,43 → 41,737 |

Каналы безопасности, возврата градиента и подъёма checker намеренно перекрываются. Текст безопасности уходит вверх, одновременно checker поднимается снизу; переход не заменён появлением через opacity. После полного появления checker до начала второй ширмы остаётся 0,75 высоты viewport вместо прежних 3,32. Переход к форме по кнопке направлен на 39,88, до начала ширмы. Горизонтальная полоса FAQ использует `data-lenis-prevent-horizontal` и `overscroll-behavior-y: auto`: горизонтальное движение остаётся внутри табов, вертикальное прокручивает страницу.

При смене media query сохраняется нативная позиция, ограниченная новой высотой страницы; Lenis синхронизируется с ней после пересчёта ScrollTrigger. При resize/orientation геометрия пересчитывается после короткого debounce, также учитывается загрузка шрифтов. При открытой экранной клавиатуре пересборка на неизменной ширине пропускается; положение формы обновляет visualViewport. `onRefresh` синхронизирует DOM с восстановленным playhead ScrollTrigger, в том числе после перезагрузки на ненулевом scroll.

## Чип и lifecycle

`ChipMedia` / `useChipMedia` изолируют видео от scroll orchestration. Видео не проигрывается циклом: задаётся последняя запрошенная позиция, ожидающий seek завершается через `seeked`. Ветка Apple включает Safari на macOS и браузеры на iPhone/iPad, в том числе Chrome, Firefox и Edge; она сохраняет все 150 WebP-кадров. Их загрузка начинается за два viewport до появления чипа, как и загрузка WebM на остальных устройствах. Скрытый video чипа в режиме Apple не получает src: кадры и завершение сцены не зависят от video seek или готовности декодера. При ошибке видео также доступен кадровый fallback. В Reduce Motion показан статичный кадр, hero video приостановлен; Lenis выключен.

При unmount и смене media query:

- `gsap.context().revert()` и `matchMedia.revert()` удаляют timeline/ScrollTrigger;
- убираются callback ticker, GSAP media-event callbacks и Lenis scroll listener, вызывается `lenis.destroy()`;
- завершаются отложенные CTA/focus tweens и resize/checker/Snackbar timers;
- удаляются resize/orientation, visualViewport, media-query, video и visibility listeners, отключается IntersectionObserver;
- видео останавливаются и освобождают src; ссылки на предзагруженные кадры очищаются;
- проверки disposed/active предотвращают запуск после позднего dynamic import или `document.fonts.ready`.

Глобальные внутренние служебные механизмы зарегистрированного GSAP-плагина не отключаются принудительно: это могло бы повредить другим сценам будущего приложения. Собственные экземпляры и callbacks компонента удаляются.

## Checker

Каталог расширен до **82 устройств**, включая **33 модели iPhone** и **38 устройств Samsung**; **10 популярных моделей** сохранены. Запросы Apple, iPhone и Samsung (включая кириллические алиасы) показывают весь соответствующий каталог с внутренним скроллом. Для уточнённых запросов остаётся максимум **5 подсказок**. Точное название имеет приоритет над fuzzy matching. Результат всегда использует официальное название из базы.

Все четыре заданных русскоязычных примера распознаются. Состояния: пустая форма → autocomplete → загрузка **720 ms** → поддерживается / не поддерживается. Неизвестная модель возвращает форму со Snackbar **10 s**. Escape закрывает подсказки/уведомление; Arrow Up/Down меняют выбранную подсказку; Enter запускает проверку. Reset и очистка сбрасывают запрос, selection, результат, таймеры, загрузку и Snackbar, возвращают фокус в пустой input и популярные модели.

Линейки iPhone XS/XR и 11–17, включая Plus, mini, Pro, Pro Max, 16e и Air, а также Galaxy S20–S26, FE, Edge, Z Fold и Z Flip дополнены по официальным спискам [Apple](https://support.apple.com/en-us/118669) и [Samsung](https://www.samsung.com/de/support/mobile-devices/galaxy-esim-und-untersttzte-netzbetreiber/). Региональные версии могут отличаться по поддержке eSIM; подсказки о регионе и проверке EID сохранены. Для моделей, отсутствующих в базе, прежнее приблизительное сопоставление остаётся.

## Accessibility

Исправлено:

- основной текст доступен через семантический `StoryTranscript`, визуальные посимвольные копии скрыты от screen reader;
- используются main/nav/section/heading/form/label/button/link, осмысленные alt и пустые alt для декора;
- combobox/listbox имеет controls, expanded, activedescendant, selected и управление клавиатурой;
- `aria-busy` и отдельный `role=status` объявляют загрузку/ошибку; фокус переходит к заголовку результата и обратно при reset;
- скрытые CTA и ещё не появившийся checker исключены из взаимодействия через inert/tabindex;
- добавлены skip-link, focus-visible, доступная при фокусе кнопка submit, увеличенная область закрытия Snackbar;
- Reduce Motion отключает smooth scroll, blur и большую часть декоративных перемещений, останавливает hero;
- zoom не ограничивается в viewport meta; на mobile input минимум 16 px; в низких окнах checker допускает внутреннюю прокрутку.

Намеренно оставлено:

- фирменный контраст: белый/оранжевый около **3,13:1**, placeholder около **3,23:1**; малый полупрозрачный текст поверх градиента требует отдельного дизайн-решения;
- исходная композиция с фиксированными размерами не гарантирует полного reflow при большом browser/text zoom; стандартный viewport сохранён, соответствие WCAG на 200–400% не заявляется;
- пункты навигации, регион, вход/меню и основной CTA результата не имеют бизнес-действий в эталоне: показаны настоящими disabled buttons. Главные CTA лендинга ведут к checker. Реальные маршруты/оформление подключения требуют отдельной интеграции;
- hero остаётся декоративным autoplay в обычном режиме. Reduce Motion его останавливает; отдельная видимая кнопка pause потребует согласованного изменения интерфейса.

## Safari/iOS и будущий Nuxt 4

**Реальный WebKit/Safari и физический iPhone в этой сессии не проверялись.** Перед выпуском нужны проверки autoplay/alpha MOV, затрат памяти 150 кадров, инерции touch, динамических панелей Safari, реальной клавиатуры, pinch zoom, VoiceOver и поворота устройства. Имитация UA подтверждает выбор ветки кода, но не возможности декодера и поведение iOS.

Для Nuxt:

1. Перенести компоненты/composables/data и public assets, подключить общие стили в конфигурации; SSR-разметку оставлять доступной. Анимационные импорты уже находятся в onMounted.
2. Заменить `asset()` на resolver с учётом Nuxt app.baseURL / CDN и согласовать пути font-face. Сейчас база — Vite `BASE_URL`.
3. Согласовать единственного владельца Lenis/ticker, если smooth scrolling станет общим для всех маршрутов. Не создавать несколько экземпляров на document.
4. Учитывать scroll restoration роутера, page transitions, обновление шрифтов/размеров и момент ScrollTrigger.refresh после завершения перехода.
5. Если применится KeepAlive, добавить управление deactivated/activated: текущая очистка рассчитана на unmount.
6. Изолировать глобальные reference CSS при встраивании в общий сайт. Проверить id и SSR hydration в конечном layout, а также перенести SEO/meta в Nuxt useHead.
7. Оставить кадровый fallback изолированным; его memory/network оптимизация — отдельная работа после измерений на iOS.

По запросу «Опубликуй» обновляются оба адреса одной Vue-версией:

В `vue/` выполнить `npm test` и `npm run build`. Из корня репозитория запустить `bash scripts/deploy-host.sh`: он загружает только `vue/dist`, создаёт новый выпуск в `/var/www/esim-landing-vue/releases` и атомарно переключает `current`. Старые выпуски сохранены для отката; старые хешированные бандлы остаются доступны уже открытым страницам. SSH использует существующий доступ к `root@31.76.74.213`; пароли и ключи в репозитории не хранятся.

Зафиксировать релевантные изменения и отправить в `origin/main`, затем дождаться успешного workflow `Deploy to GitHub Pages`. Он запускает тесты и сборку из `vue/`, публикует `vue/dist`. Относительные URL Vite (`base: './'`) позволяют использовать одну сборку в корне поддомена и по пути `/esim-landing/`.

Поддомен в Cloudflare: A → `31.76.74.213`, DNS only. Посетители подключаются непосредственно к финскому серверу; Cloudflare используется для DNS. Конфигурация HTTP virtual host — `deploy/nginx.conf` в корне проекта; внешний TCP 443 остаётся у существующего nginx stream с отдельным SNI-маршрутом eSIM на `127.0.0.1:9447`. Сертификат сервера выпускается и обновляется Certbot через HTTP webroot; после обновления сертификата eSIM deploy-hook перезагружает конфигурацию Nginx. HTML и файлы без хеша перепроверяются по ETag, хешированные JS/CSS кешируются надолго. Видео поддерживает HTTP Range.

Проверять доступность с внешнего подключения, включая полную загрузку JS/CSS, картинок результатов и видео, а также HTTP Range. Успешный HEAD или ответ изнутри VPS не подтверждает, что пользователи могут загрузить сайт. Доступность через Cloudflare может различаться между сетями; после смены режима нужно проверить и браузер, и полную загрузку файлов.

Не добавлять поддомен в Custom domain GitHub Pages: это вызвало бы перенаправление вместо двух независимых адресов. Vercel больше не является целью публикации; автодеплои Git отключены через `git.deploymentEnabled: false` в корневом и Vue `vercel.json`, существующие проекты не удалены.

## Медиа при слабом соединении и поворот чипа

`provideMediaConnection()` отделяет приблизительную оценку сети от явного запрета видео (`avoidVideo`: Save-Data/offline). Hero и чип пробуют загрузить видео даже при оценке «3G», низком downlink или высоком RTT. Каждый ассет самостоятельно проверяет загрузку/декодирование с пределом 4 секунды: hero оставляет постер при собственной ошибке/таймауте, чип переходит на ограниченную очередь WebP-кадров при собственной ошибке/таймауте загрузки либо seek. Ошибка одного ассета больше не отключает другой. Safari/iOS по-прежнему используют кадровую версию чипа из-за поддержки альфа-канала. Вращение кадров продолжается по скроллу, включая обратный ход; только Reduce Motion оставляет чип статичным.

- WebM чипа: 8 611 178 → 2 099 450 байт (−75,6%), 800×800, 150 кадров, 6 секунд; VP9 alpha, ключевой кадр каждые 5 кадров. Цвет сжат с потерями (SSIM 0,9883); альфа-канал сохранён. Исходный файл перед перепаковкой сохранён локально в игнорируемом `.qa/chip-media/`. Команда: `ffmpeg -c:v libvpx-vp9 -i chip-original.webm -an -c:v libvpx-vp9 -pix_fmt yuva420p -b:v 0 -crf 32 -g 5 -row-mt 1 -deadline good -cpu-used 4 chip-scroll.webm`.
- Видеоверсия сначала получает полный Blob, затем перематывает локальные данные. До первого декодированного кадра видна картинка. Последняя запрошенная позиция сохраняется до `seeked`; задержка декодера переводит чип на кадровый fallback.
- Safari/iOS: максимум 3 загрузки одновременно, приоритет у текущего положения, готовые кадры показываются только после `Image.decode()`. Вместо предзагрузки всех 150 кадров используются соседние кадры и редкая сетка для предварительного просмотра. Кеш держит до 40 Image-ссылок; собственный кеш браузера этим лимитом не управляется. При задержке отдельного кадра сохраняется уже декодированное изображение, очередь продолжает загружать доступные кадры.
- Поворот напрямую получает положение общего scroll timeline, без отдельного догоняния, ограничения угловой скорости и докручивания. Последняя запрошенная позиция применяется после завершения декодирования; скрытая вкладка не запрашивает новые перемотки до возвращения.
- `ending/2gb`, `ending/lightning` и `ending/footer-qr` переведены из PNG в WebP без потерь: 680 317 → 429 676 байт (−36,8%). Проверено точное совпадение RGBA всех пикселей. Ленивую загрузку и размеры оставили прежними.

Проверки этого изменения: Node-регрессии очереди кадров, позднего декодирования, возврата к фронтальному виду, оборотов и выбора статичного режима; SSR и production build. Браузерная проверка задержанных HTTP-ответов выполняется локальным тестовым прокси, отдельно от имитации Network Information. Физический iPhone и настоящий WebKit требуют отдельной проверки; имитация UA подтверждает только выбор кадровой ветки.

Видео hero продолжает играть во время частичного и полного подъёма шторки, а также при обратной прокрутке. Скрытие элементов управления через `inert` не управляет воспроизведением. При слабом соединении вращение продолжается через WebP-кадры; Reduce Motion сохраняет статичный кадр. Скрытая вкладка и unmount по-прежнему останавливают видео.

Четыре серых тезиса используют тот же `SoftBlurText` и общий расчёт поочерёдного появления слов, что и заголовки оранжевых преимуществ. Размытие и сдвиг применяются к словам; абзац сохраняет свою позицию и резкость. Для тезисов сохранены расстояния: 0,525 высоты экрана на вход, 2,1 на чтение, 0,525 на выход. Reduce Motion отключает размытие и сдвиг; обратная прокрутка воспроизводит те же фазы в обратном порядке.

На оранжевых преимуществах `featureReadingProgress()` добавляет 2 высоты экрана для чтения каждой из трёх пар на десктопе и 1 высоту для каждого из шести пунктов на мобильном. На этих участках текстовый playhead стоит в полностью проявленной фазе; вход и выход сохраняют прежнюю дистанцию. Вся последовательность занимает 14 высот вместо 8. Поворот идёт независимым линейным треком: три оборота до окончания преимуществ и ещё один до ухода определения. Последующие сцены сдвигаются на 6 высот, сохраняя собственные длительности; отдельного докручивания после скролла нет.

## Увеличение чипа перед текстом безопасности

После четырёх серых тезисов канал `chipZoom` использует центральный интервал 44,68 → 46,68 высоты экрана. Первый этап увеличения занимает 2 высоты экрана вместо исходных 3,2 (на 60% быстрее). Чип начинает увеличиваться в центре, затем растёт дальше и уходит вверх, освобождая место тексту безопасности. `chipZoomFrame()` задаёт непрерывные размеры и смещения отдельно для десктопа и мобильного. Все три слоя получают одинаковый transform; отдельного догоняния поворота и докручивания нет.

Подмена видео/кадрового слоя происходит раньше, при входе в первый серый тезис. Картинка создаётся локально из финального декодированного кадра через Canvas → PNG Blob → `Image.decode()`: используются те же контур, цвета, резкость и прозрачность. Снимок делается только после завершения последнего seek или загрузки последнего WebP-кадра. На слабом соединении источником служит уже загруженная статичная картинка. Отдельный исходник из Figma не загружается: он отличался от видео и делал замену заметной. Снимок появляется после декодирования, без кроссфейда, который менял прозрачность кромок; CSS-положение и плавающее движение у слоёв одинаковые. При обратной прокрутке видео возвращается перед серыми тезисами. Если снимок недоступен, текущий слой остаётся видимым и увеличивается по той же траектории. Reduce Motion отключает увеличение; Blob URL освобождается при unmount.

Проверки: регрессии непрерывности геометрии и общего положения видео/кадра/картинки, ранней замены, обратного скролла и Reduce Motion; production build. Браузерный стенд сравнивает пиксели финального кадра и локального снимка, положение всех слоёв, кадровую ветку, статичный режим слабого соединения и ошибку создания снимка. Имитация iPhone UA проверяет выбор кадровой ветки, а не декодирование на физическом iPhone.

Пауза после полного раскрытия оранжевого фона с чипом сокращена с 0,801 до 0,401 высоты экрана. `CHIP_INTRO_PAUSE_REDUCTION` сдвигает начало вращения, строку преимуществ и все последующие треки на 0,4 высоты раньше; длительности движения, пауз на чтение и пересечения треков сохраняются.

Мобильная кнопка «Подключить eSIM» остаётся одним DOM-узлом от hero через шторку и рулетку до чипа. Надпись сохраняет градиентную маску во всех этих фазах; цвет меняется через CSS-переменные. Переход с прозрачного текста в сплошной раньше запускал 260-мс CSS-переход от alpha 0 и вызывал мигание. Этот переход устранён; положение, действие кнопки и смена палитры сохранены.

Белая мобильная подложка под кнопкой плавно исчезает на последних 65–95% раскрытия оранжевого фона с чипом. Уход начинается до смены палитры кнопки; обратный скролл восстанавливает подложку на том же участке.

## Гибридное качество чипа при zoom (2026-10-02)

Текущая схема заменяет описанный выше снимок декодированного видео. Вращение и серые тезисы продолжают использовать существующее WebM 800×800 (или Apple-ветку WebP-кадров 640×640); отдельный кадр появляется только во время увеличения.

- `public/assets/chip-zoom-still.webp`: lossless RGBA WebP, 1350×1350, 1 496 012 байт. Источник — пользовательский `SberMobile_Esim_S020_v02.mov`, ProRes 4444 1600×1600, 25 fps, 6 секунд. Взят последний кадр 5,96 с; обрезаны только прозрачные поля до центрального квадрата 1350×1350, без увеличения исходника. Это совмещает кадр с существующим видео. Пример извлечения: `ffmpeg -ss 5.96 -i SOURCE.mov -vf crop=1350:1350 -frames:v 1 -pix_fmt rgba frame.png`; затем lossless WebP. Исходные MOV, PNG и видео сайта не изменены.
- При сравнении в размере 800×800 маски непрозрачного объекта совпали на 99,94%; среднее отличие RGB: +0,20 / +0,45 / −0,01 из 255. Цветовые CSS-фильтры не потребовались.
- `ChipMedia` содержит один `.chip-media-wrapper`. Scroll transform, размеры и idle translate/rotate принадлежат ему; все три медиа-слоя заполняют его целиком. Изолированное `plus-lighter` складывает взвешенные альфа-каналы, сохраняя плотность полупрозрачных кромок во время crossfade.
- `chipStillBlend()` использует ширину из кеша геометрии, текущий scale, DPR и intrinsic width видео/кадра. Диапазон качества — 0,70…0,98. Дополнительный плавный вход на 4…34% `chipZoom` предотвращает мгновенную замену на Retina, где лимит пикселей исчерпан ещё до увеличения. На небольших DPR1-экранах смесь завершается на существующем участке safety 0,20…0,34, резкость — до 0,42. Треки, расстояния скролла, текст, CTA и траектория не изменены этим механизмом.
- Blur задан в экранных пикселях: около 0,8 в начале, 0,28 при завершении смеси; затем плавно снимается до нуля. Деление на scale предотвращает рост blur вместе с чипом. При нулевом blur filter возвращается в `none`.
- Preload начинается на последних 10% определения eSIM, перед четырьмя серыми тезисами. Fetch выполняется один раз, изображение показывается только после `decode()` и подтверждения совпадающего фронтального кадра. Если быстрый скролл опередил загрузку, отдельная короткая фаза видимого времени плавно вводит картинку и затем снимает blur; она не меняет scroll playhead. Ошибка HTTP/декодирования оставляет видео или кадровый слой видимым. Abort и Blob URL очищаются при unmount. Кадровый режим плохого соединения также переходит на high-res still при увеличении; только Reduce Motion сохраняет прежний лёгкий источник.

Локальный стенд: `http://127.0.0.1:4179/.qa/hybrid-chip/test.html` (игнорируется Git). Кнопки before / 25% / 50% / 75% / after / max показывают контрольные фазы; Run проверяет прямой и обратный ход. Параметры `dpr=1`, `dpr=2`, `frames`, `missing`, `decodefail`, `delay` проверяют плотность, кадровую ветку и отказ загрузки. `frames` имитирует выбор Apple-ветки в Chrome, а не настоящий WebKit. Скриншоты и отчёты находятся в `.qa/hybrid-chip/`.

Ограничение: кадр 1350×1350 заметно подробнее прежних 800×800/640×640, но на максимальном desktop zoom с DPR2 он всё ещё растягивается. Для полной нативной детализации там нужен совпадающий исходный рендер большего разрешения.

Проверка этой реализации: `npm test` — 80/80, `npm run build` и `git diff --check` — успешно. В Chrome проверены desktop/mobile, DPR1/2, прямой и обратный проход, быстрые переходы, медленный проход и resize. Геометрия трёх слоёв совпала в контрольных точках. На обратном проходе восстанавливается видео. HTTP 404 и отказ decode оставляют исходный слой видимым; задержка загрузки 5 секунд даёт промежуточные значения opacity и не создаёт пустого кадра. Apple-кадровая ветка проверена через UA-стенд Chrome; реальный Safari/физический iPhone не проверены. Контрольные PNG: `.qa/hybrid-chip/screenshots/desktop-before.png`, `desktop-25percent.png`, `desktop-50percent.png`, `desktop-75percent.png`, `desktop-after.png`, `desktop-max.png`; чистый итоговый кадр — `result.png`.

Файлы этой задачи: `src/components/ChipMedia.vue`, `ChipStory.vue`; `src/composables/useChipMedia.js`, `useScrollScene.js` (DPR); `src/animation/chipStory.js`, новый `chipStillBlend.js`; новый `src/utils/chipStillLoader.js`; `src/styles/reference.css`; `public/assets/chip-zoom-still.webp`; `tests/chipPlayback.test.js`, `chipZoom.test.js`, новый `chipStillBlend.test.js`; этот README. ## Равномерное вращение чипа

Отдельный `definitionTurn` ускорял последний оборот: первые 3 оборота занимали 22 высоты экрана, последний — 3,1. Теперь один линейный `playback` задаёт 4 оборота за 25,1 высоты экрана (один оборот за 6,275), от 6,55 до 31,65. Начало/конец вращения, фронтальный финальный кадр, паузы чтения, перемещения, увеличение и гибридная подмена сохранены. Скорость зависит от расстояния прокрутки, включая обратный ход; после определения чип остаётся фронтальным, как прежде. Проверка: 81 Node-тест и production build; регрессионный тест сравнивает 1001 равномерный шаг и обратный проход на desktop/mobile, включая прежнюю границу ускорения 28,55.

Локальный просмотр: в `vite.config.js` изменения модулей анимации и компонентов/композаблов чипа вызывают полный reload вместо частичного Vue HMR. Сбой воспроизведён на участке zoom: после script HMR `ChipStory.vue` старый GSAP renderer сохранял ссылки на удалённые DOM-узлы и exposed-методы; still терял src, а video возвращался к первому кадру. Проверка восстановления вращения при слабом соединении: `chipMediaFallback.test.js` монтирует настоящий Vue composable и проверяет общую подсказку от hero, начальное медленное соединение, таймаут видео, обратный ход, high-res still и переключение Reduce Motion. Координаты, размеры и расстояния треков сохранены.

## Скорость бокового перемещения на экранах с тезисами

На desktop общий story playhead дополнительно ограничивает боковой путь: максимум 2,5 единицы в секунду, где одна единица — 20% ширины viewport. Полное перемещение между колонками занимает не меньше 0,8 секунды, возвращение из колонки в центр — не меньше 0,4. Ограничение считает пройденный путь через каждую колонку, поэтому противоположные перемещения при большом scroll-жесте не отменяют друг друга. При медленной прокрутке сохраняется прежняя геометрия. Позиции, размеры, расстояния scroll-треков и mobile сохранены; увеличение начинается после возврата в центр. Расчёт работает в существующем GSAP ticker без чтения layout и очищается при unmount.

Проверка: 90 Node-тестов и production build. Регрессии проверяют одинаковый предел на всех пяти переходах в обе стороны при 30/60/120 fps, прерывание обратным жестом и медленную прокрутку. В локальном desktop-браузере 1280×720 записаны два перехода между колонками, быстрый проход через последнюю колонку к zoom и обратный проход: пиковая скорость около 640 px/s, кадров с одновременным боковым перемещением и увеличением/подъёмом — 0.
