# Работа с проектом eSIM

- Общаться по-русски, сохранять несвязанные изменения пользователя.
- Актуальное приложение находится в `vue/`; React в корне — прежняя версия.
- Запросы «Опубликуй» и «опубликовать» разрешают публикацию текущих изменений на оба адреса:
  - https://esim-landing.ivanzlobin.com/
  - https://ivanzl9208.github.io/esim-landing/
- Vercel больше не является целью публикации. Автодеплои Git отключены в корневом и Vue `vercel.json`; существующие проекты не удалять.
- Перед публикацией выполнить `npm test` и `npm run build` в `vue/`.
- Основной сервер eSIM: `31.76.74.213` (Финляндия), SSH-пользователь `root`; публикация готовой сборки — `bash scripts/deploy-host.sh`. Прежний сервер `212.118.56.141` сохранён для отката. Сервер портфолио `135.106.228.161` не является целью публикации eSIM.
- Для GitHub проверить diff, включить только относящиеся к проекту изменения, создать коммит и отправить в `origin/main`; дождаться успешного workflow `Deploy to GitHub Pages`.
- На обоих адресах должна быть одна Vue-сборка. Проверить HTTP, файлы JS/CSS, картинки результатов и Range-запрос к видео.
- DNS основного поддомена `esim-landing.ivanzlobin.com`: A → `31.76.74.213`, Cloudflare DNS only (2026-10-05). Прежний `esim-landing-vue.ivanzlobin.com` остаётся на том же IP и перенаправляет на новый адрес с сохранением пути и query. Не менять другие записи домена и не добавлять custom domain в GitHub Pages: оба адреса публикации должны работать независимо.
- На финском сервере внешний TCP 443 обслуживает существующий nginx stream: SNI обоих поддоменов eSIM → `127.0.0.1:9447`, где отдельные HTTPS virtual hosts принимают PROXY protocol. Сохранять остальные stream-маршруты и VPN-службы; не заменять внешний listener обычным HTTPS server. Certbot продлевает оба сертификата через HTTP webroot; hook `deploy/reload-esim-nginx` установлен в `/etc/letsencrypt/renewal-hooks/deploy/reload-esim-nginx`.
- Доступность проверять с внешнего подключения: полностью скачивать JS/CSS, картинки результатов и видео, а также проверять HTTP Range. Ответ 200 изнутри сервера или только на HEAD не подтверждает загрузку сайта у пользователей.
- Не записывать пароли, закрытые ключи и токены в репозиторий или документацию. Использовать существующий SSH-доступ; при отсутствии доступа запросить его у пользователя.
